# 本机接口 v1

连接 `127.0.0.1:19606`，UTF-8 NDJSON。一行一个请求/响应，单行最多 4095 字节；32 个并发连接、32 个待执行外部任务。请求仅支持文档中的 ASCII 字段名/命令名、无符号整数和整数数组；未知、重复字段和字符串转义会被拒绝。`id` 为可选无符号 64 位整数，用于关联响应。

## 缓存

```json
{"id":1,"cmd":"snapshot"}
```

返回 `sequence`、`completed_ns`、`request_ns`、`transactions`、`failures`、`coalesced`、`cache_hits`、`queue_rejected`、`queued`、`last_error`、121 项 `registers` 和逐寄存器 `updated_ns`。未知/失效寄存器为 `null`；冷数据不会因热数据刷新而改变自身时间戳。时间是本机单调纳秒，不能作为 UTC 时间直接保存或跨机器比较。

`info` 当前与 `snapshot` 相同。未识别型号时不可写；客户端自行按型号选择物理单位缩放。设备功率通常为 HR12/13 组合的 32 位值，普通 60067 除以 100 得 W。

查询完整型号和寄存器能力表：

```json
{"id":5,"cmd":"registers"}
```

响应含 HR0–120 的原始缓存值、是否为已知地址、是否可写、raw/physical 缩放和允许的原始值上下限。只读寄存器会明确标记 `writable:false`。未知寄存器保留 raw read 能力，写入拒绝。型号未知时，电压/电流及预设寄存器不采用推测的精度和写入上限。

## 订阅

```json
{"id":2,"cmd":"subscribe","after":0}
```

该连接之后只接收新序号的快照；命令操作请使用另一连接。订阅不会触发硬件读取。`after` 是等待比给定序号更新的样本，不提供历史重放。发送阻塞达到约一秒会关闭连接。服务使用最新值模式，慢客户端可能跳过中间序号；需要逐点记录时应及时消费并检查序号连续性。

断线/CRC 失败不伪造新样本。需要观测离线状态时可在命令连接查询 `snapshot.failures`、`last_error` 和样本年龄。恢复重识别可能产生一帧包含电压/电流的初始化读取，该帧同样有唯一序号。

## 显式读取

```json
{"id":3,"cmd":"read","start":10,"count":4,"max_age_ms":200}
```

在每个请求寄存器都有效且足够新时从缓存返回，否则复用覆盖范围的进行中/待执行读取，或排队进行一次读取。

```json
{"id":3,"ok":true,"start":10,"values":[421,700,0,295]}
```

`max_age_ms` 缺省为 0，表示不能使用提交前已有的缓存，但可以共享已经进行中的读取。要避免干扰采集，普通 UI 优先使用 `snapshot` / `subscribe`。

## 写入

启动 daemon 时显式传入 `--allow-writes`。在能力表标记为 `writable:true` 的已知寄存器都可原始读写：HR8/9 设定、HR15 键锁、HR18 输出、HR19 快速预设及 HR80–119 全部 M0–M9 参数。范围按识别型号验证；RD6006P、6012/6018/6024/6030 和 RK8009 的缩放与上限分别适用。物理量与 raw 值关系为 `raw = physical × scale`。

HR72 (`0x0048`) 背光按 RD6000 官方系列手册/协议支持，raw 范围为 0–5。它和其他已知寄存器一样只需启用 `--allow-writes`。此项目档案暂不对 RK8009 启用该寄存器。HR19 的合法 raw 选择范围是 1–9，写入对应编号以切换设备的数据组；0 和大于 9 的值均拒绝。M0 为上电默认组，不提供切换到 M0。切换后应等待设备载入并回读 HR19、HR8/9。分组存储的 OVP/OCP 地址为 HR[80 + 组编号 × 4 + 2/3]。RD6006（60067，固件 1.15）实测：写 HR82 可立即更新生效中的 OVP，同时改变 M0 存储；HR83 按对应 OCP 逻辑处理。写 M1–M9 的保护存储寄存器不会立即刷新已经载入的保护，需要重新载入该组。“应用即时保护”应写 HR82/83；只有保存数据组时才写该组的四个参数。重新载入 HR19 也会重载电压、电流，不能当成无副作用的保护刷新。该固件在载入 M1 后，HR82/83 的回读仍是 M0 存储值，不能依此读出刚载入的即时保护。OVP 的立即切断行为已在真机验证；本轮无负载，未实测 OCP 触发点。

HR0 不属于此版本支持的型号时，能力表将型号相关参数标为只读，整个写入接口拒绝执行。

寄存器布局与 RD60xx 相同、只是精度和上限不同的型号，可在启动时用 `--model-profile ID,VSCALE,ISCALE,VMAX,IMAX,OVP,OCP` 登记，例如 `--model-profile 60125,100,1000,61,6.1,62,6.2`。缩放只能是 10/100/1000/10000，每个上限 × 缩放不得超过 65535；内置型号 ID 不能覆盖，参数无效时 daemon 以退出码 2 结束。登记后能力表 `model_name` 为 `Custom`，该 ID 按给定缩放和上限放开与内置型号相同的写入范围。C ABI 对应 `rc_register_model()`，需在 `rc_create()` 之前调用，最多 8 个 ID。缩放填错会使写入的物理值相差 10 倍以上，应先只读核对读数与设备屏幕一致。所有请求使用 raw 整数；物理量换算由同一能力表提供的 `scale` 完成。

HR72 的依据是 [Joy-IT RD60xx Modbus Protocol](https://joy-it.net/files/files/Produkte/JT-PS1440-C-Pro/MODBUS_Protocol_RD60xx_PSxx.pdf) 中的 `0x0048 BACKLIGHT R/W 0..5`，以及 [RD6000 用户手册](https://joy-it.net/files/files/Produkte/JT-RD6006-C/JT-RD6000-Manual_2023-02-10.pdf) 中的六档亮度说明。

单寄存器示例：

```json
{"id":4,"cmd":"write","start":8,"values":[420]}
```

多个连续、且每个成员都可写的寄存器需额外传入 `--allow-multiwrite`，用 0x10。支持 HR8–9 或一个预设槽内四个连续字段；不能跨越只读寄存器。整项范围和数值验证通过后才发送。未启用批写时返回不支持，不隐式拆成多个写入。写入不合并、不自动重试。

```json
{"id":4,"ok":true,"acknowledged":true}
```

确认不代表物理输出已经达到目标，也不保证固件事务原子性。需要时对相关范围回读；不会无条件读全表。

默认绑定回环地址且只读；允许写入后，本机可连接此端口的进程均有相应权限。当前接口无用户认证，不能转发为公网控制接口。多用户隔离需求后续可增加 Unix Socket/命名管道 ACL。

## 错误

错误形如 `{"id":4,"ok":false,"error":-8,"message":"register is read-only"}`。

| 值 | 含义 |
|---|---|
| -1 | 传输 I/O 错误 |
| -2 | 响应超时 |
| -3 | 响应长度/地址/功能码/写回显错误 |
| -4 | CRC 错误 |
| -5 | 核心关闭 |
| -6 | raw 值越界或 JSON/参数无效 |
| -7 | 待执行队列已满 |
| -8 | 只读模式 |
| -9 | 未支持型号、推断写入未启用、批写/功能码不支持或从机异常响应 |
| -10 | 内存不足 |

## 调度限制

正在执行的 RTU 事务不可抢占；用户请求、采集和写入共享单链路。每项外部事务后，若热采集已到期就执行采集；超过 500 ms 的读参与公平调度。真机并发写将采样 P95 从约 717 ms 降到约 287 ms，详见读写调度实测。请求过多时不会通过并行发帧增加吞吐。超时后采取有限的排空与退避，无法提供硬实时截止期保证。
