# Linux 真机读写调度测试

设备为 RD6006 衍生型号 60067、固件 HR3=115、CH340、115200 8N1。写入测试只将 HR8=420、HR9=6100、HR72=4 写回刚读取的原值；未改变输出、预设或背光设置。

## 结果

| 项目 | 测试 | 结果 |
|---|---:|---:|
| 空闲热采样间隔 | 50 帧 | P50 143.83 ms，P95 144.09 ms |
| 单寄存器 `0x06` 写入延迟 | HR8/9/72 各 20 次 | P50 约 287 ms |
| 连续 `0x10` 写入延迟 | HR8–9，30 次 | P50 287.24 ms |
| 并发写时采样间隔 | 4 客户端、40 次写 | 新策略 P50 287.01 ms，P95 287.40 ms，最大 287.59 ms |
| 并发写完成时间 | 40 次写 | 17.1 秒，0 次通信失败、0 序号缺口 |

对照旧策略，并发写时采样间隔 P95 为 716.98 ms、最大 717.45 ms。新策略降低了写入负载造成的采样尾延迟；空闲时采样表现不变。`0x10` 可在一笔事务中更新连续寄存器，但单次事务延迟与 `0x06` 接近。

## 结论边界

数据包含 IPC、调度排队和串口响应，不是裸总线线速。测试只覆盖上述设备与短时负载，不能推导其他型号、链路或故障场景的性能上限。设备回显和原值读回确认了协议交互，但没有验证改变设定值后的实际输出效果。
